# 港口集装箱装卸延误分级

`container-delay-triage` 面向海陵港集装箱运营台。调度员把船次窗口、箱单核验、闸口事件汇总为人工交叉特征，worker 用 LogisticRegression 给延误案件分级，再由主管确认调度动作。

## 账号

- `operator / operator123` 现场调度员，可维护船次、箱单、闸口记录并发起分级
- `supervisor / supervisor123` 船舶值班主管，可处理查验状态、冲正闸口、派发调度动作
- `viewer / viewer123` 运营观察员，只读看板和分级结果

## 运行

```bash
docker compose up -d --build
# 浏览器访问 http://localhost:18262
```

## 交付范围

船期窗口、箱单核验、闸口记录、延误案件、调度处置五个业务模块，包含查验未结束拒绝普通延误和重复闸口必须冲正两个异常分支。算法任务由 Redis 队列交给 worker，结果写回 `analysis_jobs` 和 `delay_cases`。


## 业务核验模块

登录后打开页面右下角的「业务核验」。可从实时业务台账筛选记录、导出所选结果，主管可对当前证据签认并填写说明。

- **查验积压与船期** 按挂靠汇总海关状态和封签问题，优先处理阻塞箱量最大的船期。
- **闸口拥堵分布** 分闸口和作业日统计有效停留，冲正记录单列；高于 60 分钟的有效记录列为拥堵。
- **调度交接时限** 把案件等级、责任人和到期时间放在同一交接表，区分未完成逾期和完成后超时。

### 二次扩展核验

- **装船进闸凭证核对** 逐箱核对有效进闸凭证与查验状态，区分未放行、缺凭证和已齐备。
- **分流阻断恢复队列** 结合案件状态与最近模型任务，区分业务输入待修、模型失败待重跑和待人工定级。

## 业务处置与验收

登录后打开「港口异常交接」。操作员提交结果、凭证号和说明，主管可复核关闭或退回补证，观察员可查看记录。关闭时复查源业务状态，处置历史保留每次操作。

- 重复进闸冲正复核
- 分流恢复验收
- 海关放行交接

## 改挂工作台

登录后打开右下角「改挂工作台」。主管可勾选原船次上的一批箱，选择接收船次后试算，同一模型（`src/model.py`，worker 与接口共用）同时给出两船次改挂前后的严重延误概率（`P(major)+P(critical)`）。

- **确认条件**：原船次严重延误概率下降，且接收船次不上升，才允许确认。
- **试算有效期**：试算记录会保存当时两船次的箱单与有效闸口记录摘要。试算期间箱单照常更新；任一摘要变化，工作台即标记该试算失效，确认接口返回 `EVIDENCE_CHANGED`，须重新试算。
- **整批办理**：确认时按箱单逐笔核对，整批箱要么全部改挂、要么全部留在原船，不产生半批。
- **并发与重试**：确认需带 8–80 位幂等键。中断后用同一幂等键重试，或对已确认试算再次确认，都只返回原办理结果，不重复改挂。两名主管同时确认时按船次加锁依次执行，后到者会因证据已变而整批放弃。
- **查询**：工作台列出每次试算的两船次前后概率、失效状态和办理结果；`viewer` 只读。

接口：`GET/POST /api/rehang/trials`、`GET /api/rehang/trials/{id}`、`POST /api/rehang/trials/{id}/recalculate`、`POST /api/rehang/trials/{id}/confirm`。演示数据中的 `CALL-LINK-20261121` 为可接收改挂的加班接驳船。

测试：`python3 -m pytest backend/tests/test_rehang.py -q`（使用 SQLite，无需启动容器）。
